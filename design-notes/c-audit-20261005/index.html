C 端 PC / 移动端全量审查

2026-10-05 · 原型、页面需求、产品方案、模块流程与线上对照

当前框架可以继续使用，不建议整体重做。最优先的问题是：同一详情存在两套渲染路径、两端业务说明不一致，以及页面需求更新后产品方案和模块流程仍停留在旧版本。

本轮列出 16 项确定问题、5 项优化建议、4 项待决策事项。确定问题中，4 项是浏览可见的问题，12 项是需求与信息架构问题；二者有共同根因，不代表需要做 16 次独立改版。未发现本轮正常页面普遍无法加载或普遍横向溢出的情况。

审查口径与范围

  • 以本次已确认的新产品决定为准，线上用于核对业务内容和真实入口，不要求恢复旧站视觉、栏目名称或已删除页面。
  • 原型负责说明布局、信息、状态和动作去向。未接 API、模拟二维码、演示积分、模拟任务与评论，不计为原型缺陷。
  • 覆盖 36 个页面需求键，按 PC / 移动端实际归属查看正常页面；兼容路由按实际目的地归并，不能理解为 72 个独立页面。另检查关键类型样本、弹层、滚动与代表性入口。
  • 主视口为 PC 1280×720、移动端 390×844，并查看阅读台实际 iframe 入口。属于本轮设计与交接审查，不是所有浏览器、尺寸、登录组合和数据组合的穷举验收。
  • 线上实看首页、签到弹层、邀请及规则、教程列表与详情、国庆活动详情，以及移动积分、商城、生成和社区。真实 C 端源码另作只读核对。未执行真实生成、签到领奖、兑换、绑定或发布。
  • 仅新增审查报告与本地截图，本轮没有修改产品原型。需求与 IA 由 GPT-6 Astra / medium 独立核查；真实源码由复用代理核查，未将其实际模型作未经确认的声明。

一、优先修正的页面问题

UI-01 · P1 · PC 教程详情：正常入口会退回旧的通用详情

现象：从教程列表点击“旧照片修复：从判断破损到复查”，进入标题、署名和一张超大封面的单列布局；加入 embed=1 的样本却是已设计好的“左封面、右介绍与开始学习、下方目录正文”布局。两者不是仅内容长短不同。

影响：已有专用 PC 教程模板，但普通发布数据分支未复用；用户从实际演示入口进入时，看不到同一套 PC 阅读结构；以样本截图交付容易漏掉此问题。

复现：PC 教程列表 → 点击上述教程；对照 page=tutorial&device=pc&embed=1。本次普通阅读台 iframe 也未带 embed。当前浏览器存在 B 端发布样本，记录及发布版本参与分支选择，因此其他干净会话未必以相同数据触发。

依据：c-prototype/published.tsx:18-22,45-56 根据 embed、id、发布版本选择渲染分支；该分支没有复用 PC 教程布局。截图：pc-tutorial-from-list.png、pc-tutorial-_embed_1.png。

建议：让发布数据与静态样本只改变内容，统一进入 PC 教程模板。验收覆盖阅读台正常页、列表点击、带 id 链接三种入口。

UI-02 · P1 · AI 应用：同一“文案改写”在两端表达不同的可用性

现象：PC 按钮为“暂未开放使用”；移动端却显示可点击的“在 MakeNow 中使用”，点后进入旧承接说明页，才告知定向链接待配置。该承接页还使用了照片修复缩略图。

影响：用户会把移动端按钮理解为可以使用，而 PC 显示不可用。问题是入口承诺和样本身份不一致，不是要求原型接通 MakeNow 生产任务。

依据：c-prototype/published.tsx:24-36，PC 的目标地址校验与移动端的 Boolean(d.entry) / appHandoffUrl 分支不同；app-desktop.tsx:10-11 校验 HTTPS 目标。截图：pc-app.png、mobile-app.png、mobile-app-handoff.png。最后一张为移动设备参数在宽屏中检查去向，不能作为手机响应式截图。

建议：统一“未配置、可用、暂停”的展示依据。已配置的 PC 入口直接去目标；手机按设备能力显示使用或电脑端提示；未配置不能先承诺使用再转占位说明。旧说明页若保留为研究资料，不挂到普通用户 CTA。

UI-03 · P2 · 移动邀请规则遗漏 PC 已补齐的重要内容

现象：手机规则弹层只有注册、互动、发布三个阶段及一句唯一关系说明；PC 已有每日 / 每月限额、内容审核和异常处理。手机弹层没有可继续滚出的这些内容。

影响：同一邀请业务，两端用户能读到的奖励限制不同。只写“以系统校验为准”不能替代具体限额规则。

线上对照：本轮线上规则仍包含每日 2,000、每月 10,000 积分的示例额度及有效性处理。保留现有配置口径即可，不在原型中实现结算。

依据：c-prototype/personal.tsx:1328-1331,1346 是两套规则正文。截图：pc-invite-rules.png、mobile-invite-rules.png。

建议：两端共用规则内容，PC 表格、手机分段，弹层内容可滚动且关闭按钮可见。金额最终由运营配置，不因本报告再次定版金额。

UI-04 · P2 · 移动“我的”管理卡片操作仍在状态行

现象：编辑、删除图标位于第三行状态右侧，没有和标题上沿对齐；PC 已在标题行。

影响：与前面已确认的“右侧操作上移、与标题对齐，图片不拉伸”不一致，且五类管理内容的统一性仍不完整。

依据：c-prototype/personal.css:723 将操作放在 grid-row:3；:792 仅 PC 覆盖为第一行。截图：mobile-mine.png、pc-mine.png。

建议：手机也使用标题区右侧操作，预留双图标宽度；长标题最多两行，状态与时间在正文区。不要通过拉高图片补齐。

三、建议优化，不视为功能缺陷

UX-01 · PC 应用的可用主按钮看起来像禁用

电商套图、选品分析等可用按钮使用很浅的灰底；不可用按钮也用灰底，只靠字色分辨。建议可用主 CTA 使用当前站点明确的主按钮样式，禁用保留弱化样式。截图：pc-app-_state_app-analysis_embed_1.png 与 pc-app-_embed_1.png。这是操作层级优化，不涉及 MakeNow 功能真实性。

UX-02 · PC 图片作品右栏出现内滚动，阅读边界不够清楚

在 1280×720 的图片作品样本中，右侧作者、操作、提示词、关联应用超出可视高度，右沿出现内滚动条，分享文字和末尾箭头靠近滚动边缘。视频 / 文本样本较短，不明显。建议给右栏内容预留滚动条内边距，并优先折叠长提示词 / 次要关联内容；保留面板常驻目标。不要为追求绝对不滚动而裁掉功能。截图：pc-work-_state_work-image_embed_1.png。

UX-03 · 手机未绑定账号多了一层“立即绑定”中间页

“去绑定”先打开仅含介绍和“立即绑定”的弹层，再打开真正手机号表单。表单并未缺失，已实际点到。建议未绑定直接展示表单 / 微信二维码；已绑定保留更换和解绑的管理页。截图：mobile-phone-bind.png、mobile-phone-bind-form.png。

UX-04 · 正常首页样本偏少，不利于演示内容流

本次手机首页“全部”只有两条作品，很快出现“没有更多了”。当前会话可能受运营 / 发布样本影响，不能据此断言所有会话均如此。建议阅读台固定一个有足够内容的正常样本，展示横竖图和视频，也便于检查滚动分类。无需接真实分页。截图：mobile-home.png。

UX-05 · 积分中心演示数据需要自洽

PC 近七日为 +0，但最近流水展示活动 / 邀请加分；PC 待到账为 0，手机为“—”。固定数字可以用于原型，但同屏统计与流水最好使用同一组样本；未知与明确为零也应区分。仅修改示例即可，不需要真实账务计算。证据：personal.tsx:1224-1238，截图 pc-points.png、mobile-points.png。

四、需要确认的产品边界

D-01 · 限时积分是否继续保留

真实代码有即将到期积分查询与顶栏提醒，而当前积分页没有定义到期信息。若新版本继续保留限时积分，应有到期数量 / 时间及明细入口；若取消，需明确旧积分如何解释。本次未确认生产账号具体到期金额，不把本地接口定义当作现行结算事实。

D-02 · 去 MakeNow 是否承诺同账号继续

真实 C 端已有账号互通跳转能力；当前原型按配置打开公开目标。需要说明 CTA 是普通外链还是继承登录身份。账号互通不代表素材传递、结果回传或积分互通，也不要求原型实现票据。

D-03 · 两端内容分类是否同一套业务身份

PC 使用“设计与视觉”等分类，手机出现“设计”等短名。不同显示密度可以保留，建议明确同一分类 ID 与两端名称映射，避免研发各维护一套；本次没有证据证明真实分类数据已错。

D-04 · 外部作品没有单一提示词时如何发布

当前已确认提示词必填；详情又允许参数不公开，两者本身不矛盾。尚需定义外部多轮编辑、未保留提示词的供稿是否允许“不适用 / 未保留”。本报告不擅自放宽必填，只指出投稿供给边界尚未写清。

五、已检查且不建议反复重做的部分

  • PC 圈子已具备推荐 / 已加入切换、右栏用户与圈子信息、置顶消息、带数量的操作、就地评论和回复。滚动后分类栏及右栏仍可见。
  • PC 生成图片、剧本、视频样本能承载不同内容；视频生成中反馈已与结果媒体宽度接近，状态文字没有之前的挤压错位。输入区固定、记录区可滚动，底部反馈可滚到。
  • 图片 / 视频 / 文本作品采用共同 PC 详情骨架；提示词与同款入口已展示。需要优化右栏密度，不必再拆三套详情页。
  • 搜索已有默认推荐、命中、无结果；PC 搜索弹层四个专题并排。手机命中样本的图片能铺满卡片。
  • 兑换确认、成功、积分不足、失败可展示；PC 居中、手机底部承载。删除确认也已居中，按钮没有占满整张弹层。
  • 账号绑定表单存在；绑定模块位于保存前。二维码可以继续使用虚拟图，不要求真实短信 / 微信授权。
  • 签到按七天和连签奖励展示，PC / 手机均为弹层；国庆任务以自动发放说明展示，没有必要恢复手动领取按钮。
  • 作者主页只保留作品 / 帖子，官方维护教程和应用的边界应继续保持。
  • 通用反馈已能滚到提交反馈底部；轻提示在浮层显示，不占正文布局。无需恢复一大批独立异常页面。

七、线上对照结论

本轮实看确认用于本次判断的事实对新版的含义
首页 / 签到线上导航有积分与签到；签到是七日 + 连签弹层原型业务结构基本一致，保留新版统一视觉
邀请规则有三个奖励阶段、每日 / 每月上限、有效与异常处理手机规则应补齐内容，不能只同步 PC
教程列表与详情官方教程有分类、完整正文、学习路径与开始学习原型已有相应 PC 模板，应确保实际入口使用它
国庆详情说明为富文本，任务与邀请奖励分开；旧站仍见已领奖用词保留后端维护说明；以已确认自动发放决定为准，不恢复旧按钮
手机积分 / 商城余额、统计、活动任务、商品分组及兑换记录入口存在新版精简重复标题和调整入口可以保留
手机生成 / 社区生成含三种创作类型、材料、参数、活动；社区是聚合栏目不应因 MakeNow 承载应用而删除社区自身生成

公开来源：首页 ↗、邀请 ↗、教程列表 ↗、教程详情 ↗、国庆活动 ↗、积分 ↗、商城 ↗、生成 ↗、社区 ↗。页面会随登录态、配置和时间变化，本报告只描述本次只读观察。

真实源码另有兑换未知结果、生成轮询超时、解绑验证的研发核对项，见 online-code-review.md。这些不计入上述 16 项原型问题，也不据本地代码推断生产已发生故障。

八、建议处理顺序

  1. 先统一教程详情模板与 AI 应用入口承诺，确保“看到的设计”和“实际点进去”一致。
