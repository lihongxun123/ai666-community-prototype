# 多元拾光重大改版：B 端架构与需求底稿

更新：2026-09-25｜已确认架构底稿；具体操作及新增待定项见[原型前评审入口](product-requirements-review.md)，未作真实能力验收

## 范围

承接已确认的移动端架构，定义内容组织、生产、管理与维护。研究站原型、真实 C/B 端代码与线上能力保持独立边界；本文确认的是改版需求，不代表已经实现。

## 已确认：管理对象与关系

| 对象 | 职责 | 关系与边界 |
| --- | --- | --- |
| 作品、帖子、教程 | 承载成果、表达、经验和方法 | 可关联应用或资源，也可独立发布 |
| AI 应用 | 提供可使用的能力，具有明确输入和输出 | 可依赖工作流，不等同于工作流文件 |
| 工作流、画布项目等资源 | 供下载、复用或继续编辑 | 简单附件随内容管理；被多处引用、需要持续复用和更新的资源独立维护 |
| 专题 | 按主题编排内容和应用 | 收录同一原对象，不复制为另一份内容 |
| 圈子 | 围绕共同兴趣组织成员、发布和交流 | 管理归属与讨论，专题式编排由专题承接 |

- 深度案例先作为内容的表达方式，不新增独立发布类型。
- 不要求作品、教程、资源和应用成套提供；只发布成果也成立。
- 收录专题不要求作者补齐教程或应用。
- 内容编辑、专题编排、应用与资源维护职责明确，操作界面可以关联；对象划分不直接决定后台菜单数量。

## 已确认：内容归属判断

按内容主要目的区分管理对象：

| 内容 | 归属 | 判断依据 |
| --- | --- | --- |
| 一张海报、一组角色图、一段视频 | 作品 | 主要展示创作结果 |
| 展示作品，同时附带简短心得或 Prompt | 作品 | 附加说明不改变展示成果的主要目的 |
| 分析多次失败、比较方法、分享经验或提问 | 帖子 | 主要表达观点、过程或发起讨论 |
| 系统讲解准备条件、步骤和注意事项 | 教程 | 主要帮助别人理解或完成操作 |
| 输入信息即可运行的工具 | AI 应用 | 主要提供实际使用能力 |
| 可下载或继续编辑的工作流、画布项目、模板文件 | 资源 | 主要供复用和编辑 |

本节明确内容归属，不改变已确认的生产权限：普通用户经验帖不因内容深入而强制转换为官方教程。当前内容范围为文字、图片、视频，媒体组合与初始限制已按 D-B04 确认，真实容量仍待核验。

## 已确认：生产来源与职责

| 来源 | 生产与提交方式 | B 端承接 |
| --- | --- | --- |
| 普通用户 | 在 C 端发布作品、帖子，分享经验、过程和问题 | 审核、治理、精选及专题收录；不因内容深入要求改用另一种发布方式 |
| 合作作者 | 提供深度稿件、过程材料或资源，初期可人工交稿 | 编辑整理、返修、核对授权与署名；暂不另建作者投稿后台 |
| 官方编辑 | 制作官方教程、编排专题、配置推荐位置 | 在 B 端编辑与发布；引用或改编作者材料时保留来源并取得相应授权 |
| 应用或资源提供者 | 提供可用应用或资源，以及示例、依赖和维护说明 | 技术或维护者核验，编辑完善介绍后上架；初期不开放任意用户直接上架 |

- 用户经验被精选后仍是原作者内容；整理为官方教程属于另一次编辑生产，需要明确授权与署名。
- 应用介绍编辑完成不代表应用可用；上架前必须明确使用方式、适配设备和维护责任。
- 本节确定生产分工，不代表审核状态、具体表单字段或实际责任人已经确定。

## 已确认：审核、公开、编排与可用性

四类判断分开管理，不因此增加四轮审批：

| 判断 | 职责 |
| --- | --- |
| 审核 | 判断内容是否符合公开要求；通过后可以暂不发布 |
| 公开 | 决定用户能否访问原内容 |
| 编排与推荐 | 决定专题收录、首页推荐等展示位置；撤推荐不改变原内容公开状态 |
| 应用或资源可用性 | 决定是否允许运行、下载或编辑；维护中可保留介绍并暂停受影响操作 |

- 撤销推荐只移除对应推荐位置，原内容与讨论保留。
- 内容下架或撤回后，公开列表、专题和推荐位不再展示；旧链接提供明确的不可访问提示。
- 应用或资源失效时，暂停受影响的使用入口并说明原因；关联教程可继续阅读，并提示资源暂不可用。以可直接使用为目的的推荐同步暂停。
- 修复后经核验恢复使用；此前撤掉的运营推荐由编辑决定是否恢复。
- B 端需要定位资源被哪些教程、专题等引用，以便处理影响；不因单个资源失效而一并下架所有引用内容。
- 首期可由维护者手动标记失效，不承诺自动检测。

## 已确认：专题编排与发布

首期专题由官方编辑创建和维护。

| 操作 | 要求 |
| --- | --- |
| 设置信息 | 标题、封面、简介，说明主题与适用人群 |
| 收录内容 | 搜索并选择已有作品、帖子、教程、AI 应用；需要时关联独立资源 |
| 编排顺序 | 支持直接排序、可选分组标题与简短说明；不强制分组或凑齐内容类型 |
| 推荐理由 | 可选填写收录理由与适用问题，不改动原作者正文 |
| 预览与发布 | 查看移动端、PC 呈现和入口，再发布专题 |
| 持续维护 | 增删收录、调整顺序、处理失效项；移出专题不删除原内容 |

- 专题发布后可在专题列表访问；首页专题区或 Banner 的推荐由对应展示位另行配置。
- 编排调整先保存、预览，发布更新后对外生效；原内容下架等状态联动仍即时生效。
- 手机可浏览专题全部公开内容；需要 PC 操作的应用或资源明确标识，进入使用环节时提供 PC 访问提示。
- 专题可以是作品合集，也可以组织案例、教程和应用，不要求按学习课程组织。

## 已确认：圈子创建与维护

首期采用官方建圈、指定负责人、用户自由参与的方式。

| 事项 | 规则 |
| --- | --- |
| 创建圈子 | 官方在 B 端设置名称、封面和简介；暂不开放用户自助建圈 |
| 维护责任 | 每个公开圈子有明确的运营负责人，负责回应、组织讨论和处理问题；同一人可负责多个圈子 |
| 用户参与 | 公开圈子可浏览，发布与互动需登录；不强制先加入圈子 |
| 日常运营 | 维护公告、置顶有帮助的讨论；圈内置顶不自动成为全站精选或首页推荐 |
| 内容治理 | 偏离圈子主题的内容可移出圈子，原内容保留；违规内容通过平台审核治理处理 |
| 权限范围 | 首期由内部运营使用 B 端；邀请作者参与答疑不自动授予后台管理权限 |

首期不建设复杂的圈主等级或成员权限体系。

## 已确认：应用与独立资源的最低上架要求

| 信息 | 要求 |
| --- | --- |
| 名称、介绍与示例 | 说明用途及预期结果 |
| 使用方式 | AI 应用明确 MakeNow 对应工具入口；独立资源按实际权限说明查看、复制或下载方式 |
| 使用条件 | 说明输入、工具或依赖，以及额外账号或费用要求 |
| 设备适配 | 按具体操作明确手机可直接使用或需要 PC |
| 来源与许可 | 明确提供者、平台展示与分发许可，以及用户复用范围 |
| 版本与维护 | 记录当前版本或更新时间、维护负责人 |
| 核验记录 | 记录核验人、时间、验证的使用方式、结果与已知限制 |

- 应用侧重输入、输出和运行入口；资源侧重文件或项目、依赖和导入方式，不使用完全相同的表单。普通内容附件不套用整套要求。
- 首期流程：登记材料、补齐介绍与使用条件、核验实际可用性、发布。
- 资料不齐可保存草稿；入口未验证、授权不明确或没有维护责任人的，暂不上架。
- C 端展示使用所需信息；内部负责人和核验记录留在 B 端。

## 已确认：应用与资源更新

| 变化 | 处理要求 |
| --- | --- |
| 修改封面、介绍或错别字 | 保存、预览后发布；不影响使用能力的修改不要求重新验证使用能力 |
| 更换文件、运行入口、依赖或输入输出 | 形成待发布更新，重新核验受影响的使用方式；核验期间保留仍可用的公开版本 |
| 更新使原教程步骤不再适用 | 展示关联内容清单，由编辑确认修订或添加版本提示；不自动改写教程 |
| 已公开版本失效 | 立即暂停受影响操作，不等待新版完成；沿用失效提示与推荐处理规则 |

- 首期保留更新说明、必要的版本标识和核验记录，暂不建设面向用户的多版本选择系统。
- 外部工具自行更新时，由维护者核查后处理，不承诺自动检测或控制外部版本。

## 已确认：评论交流、审核治理与内部维护

| 类型 | 入口 | 处理责任 |
| --- | --- | --- |
| 普通提问、经验交流 | 原内容评论区或圈子 | 作者、圈子运营参与回应 |
| 违规内容核查 | 内部审核治理 | 平台审核人员按治理规则处理 |

- 内容编辑和能力维护者按职责核查所维护对象；确认应用或资源失效后暂停受影响操作，修复并核验后恢复使用，运营推荐另行判断。
- 平台审核治理独立运行；核查违规内容不授予任意改写用户正文的权限。本期不设置用户举报受理与结果回传。

## 已确认：后台职责与权限

按职责授权，同一人可兼任多项职责，不强制多人审批。

| 职责 | 操作范围 |
| --- | --- |
| 内容编辑与运营 | 编辑官方内容、编排专题、维护圈子；具备发布或推荐权限后执行对应操作 |
| 审核治理 | 审核内容、核查并下架违规内容；不直接改写用户正文 |
| 应用与资源维护 | 更新资源、填写核验结果、暂停失效操作；修复并核验后恢复使用 |
| 管理员 | 配置账号权限、分配负责人；兼任其他职责时仍遵守核验和发布要求 |

- 编辑权限不自动包含发布权限，发布权限不自动包含推荐权限；首期可以授予同一名运营。
- 维护者可及时暂停故障入口，核验后恢复使用；重新进入推荐位置由具有推荐权限的人决定。
- 下架、暂停、恢复、发布更新及权限变更保留操作记录，包括操作人、时间、对象和必要说明。
- 外部合作作者通过交稿、沟通参与，暂不因此开通 B 端账号。

## 已确认：教程编辑结构

采用灵活正文、必要信息与可选关联，不以增加必填字段定义内容深度。

| 部分 | 要求 |
| --- | --- |
| 基础信息 | 标题、封面、简介，说明解决的问题和适用人群 |
| 正文 | 支持图文、视频和章节；按内容需要组织，不强制统一步骤模板 |
| 使用条件 | 涉及实际操作时，说明工具、必要准备和设备限制 |
| 关联内容 | 可关联作品、应用或独立资源，放在相关讲解位置；不要求必须附带资源 |
| 来源与署名 | 区分官方原创、合作供稿、授权改编；明确作者与编辑身份，授权依据留在后台 |
| 维护信息 | 内部明确维护负责人；涉及工具或资源版本时注明适用版本或核验时间 |

- 案例可侧重选择与取舍，操作教程可侧重步骤与限制，不要求全部组织为课程。
- 作者提供材料，编辑整理；缺少关键事实、授权或教程使用所必需的可用资源时，先保存草稿并补充材料。
- 普通用户经验帖继续轻发布，被精选不要求改为官方教程。

## 已确认：分类、标签、专题与圈子的分工

| 组织方式 | 职责 | 管理方式 |
| --- | --- | --- |
| 分类 | 提供相对稳定的浏览与筛选入口 | 运营维护名称、顺序和适用内容范围 |
| 标签 | 补充场景、工具、风格等特征，方便检索 | 按需要使用，不要求每篇内容填满 |
| 专题 | 围绕主题精选并编排内容 | 编辑主动收录、排序、填写推荐理由 |
| 圈子 | 组织用户持续发布与交流 | 维护交流范围、内容归属和讨论秩序 |

- 后台统一维护组织关系，不同内容不必套用同一套分类；具体分类名称结合实际内容另行确定。
- 带有某个标签不自动进入同名专题或圈子。
- 收录专题、归属圈子不改变原内容类型与作者。
- 普通用户发布保持轻量，不要求同时选择分类、标签、专题和圈子。
- 后台具备标签管理不意味着 C 端新增标签频道。

## AI 应用供给与维护细化方案

2026-09-25｜供给优先级及不建设任意工程自动部署平台的本期边界已确认；具体接入、人员与接口仍待落实，非生产能力声明。

已确认基础：应用按明确任务定义，交互形式属于属性；社区统一维护露出与介绍，全部 AI 应用由 MakeNow 承接输入、生成、费用、任务与结果。前期复杂内容由官方后台维护，提供者供稿，核验后发布；后续作者入口维护同一应用身份，不另建副本。已有最低上架要求、状态分离和更新规则继续适用，不增加重复审批。未来电商 Agent 尚未上线，不进入当前承接配置。

### 谁提供什么

| 供给情形 | 提供材料 | 本期建议处理 |
| --- | --- | --- |
| 官方已有工具，如 MakeNow 模特换背景 | 明确任务、输入输出、入口、效果示例、使用条件及能力维护人 | 优先登记；经核验后由社区介绍、MakeNow 执行，不因同属官方免除核验 |
| 创作者提供工作流/画布/模板，尚无可用应用 | 工程、说明、依赖、许可、维护承诺 | 先按资源承接；有明确用户任务且官方愿意承担执行维护时，再评估封装应用。资源可独立发布，不被应用评估阻塞 |
| 创作者或合作方已有可运行应用 | 真实入口/可接入能力、输入输出、示例、账号费用条件、授权与维护人 | 核验后讨论具体接入；不默认为官方托管，不凭收录将第三方执行费用并入社区计费 |

供给来源与执行方分开：官方或作者提供的候选，都须在 MakeNow 落实对应可用能力及维护责任；不能仅凭填写社区应用介绍自动获得运行能力。

### 谁维护什么

| 职责 | 维护范围 | 边界 |
| --- | --- | --- |
| 应用提供者 | 方法/能力、原始材料、授权、变更通知 | 提供者署名不等于平台内容编辑署名 |
| 内容维护者（前期官方编辑） | 名称、用途、示例、说明、条件、关联内容、发布与展示 | 不在内容表单里重新配置底层模型和执行工程 |
| 能力维护者 | 输入输出、依赖、执行、费用规则、结果、故障修复与可用性核验 | 每项应用落实负责人；不默认把所有作者工程运维交给编辑 |
| 平台运营/治理 | 公开要求、推荐编排、独立审核治理及下架 | 推荐、公开与可用性沿用已确认分离规则 |

以上是职责，可以由同一人兼任，不要求新增四个团队、角色系统或四轮审批。后台保留内部维护联系与核验信息，C 端仅展示使用所需内容。

### 从供给到维护

1. 收稿登记：确认是可运行应用还是资源，登记提供者、实际使用路径和维护责任；前期人工供稿即可，不新建投稿系统。
2. 整理介绍：补齐用途、输入输出、示例与条件。资料不足可存草稿，不将“开发中”能力伪装成可使用应用。
3. 核验使用：在获准的测试条件下检查社区到 MakeNow 定向打开、登录返回，以及 MakeNow 的输入到结果、费用提示、错误处理及设备要求。不因有按钮就通过；生产深链接未通过前不标为已接通。
4. 发布：由有权限的人员发布应用内容与有效入口；推荐可另行选择，不要求所有上架应用都进入首页。
5. 更新：文案/封面等不影响能力的修改按原流程预览发布；输入输出、入口、依赖或运行条件变化形成待发布更新，核验受影响路径。仍可用的旧版保留；已经失效时立即暂停受影响操作。
6. 故障维护：内容问题由编辑处理，运行问题由能力维护者处理；恢复使用前核验，恢复运营推荐另行判断。暂不承诺自动监控。

MakeNow 样本：模特换背景已有明确工具工作区，可作为官方应用登记候选；目前只读确认界面，尚未完成生成和费用验收。若创作者提交一份同类换背景工作流，它首先是一项资源；是否封装为应用取决于任务价值、授权及执行维护是否落实，不因主题相似重复登记一个没有实际入口的应用。

### 已确认的供给顺序与未定边界

本期已确认：先以官方已有可运行能力建立应用供给，再精选创作者资源评估应用化；不建设任意用户上传工程即自动部署为应用的平台。创作者资源仍可独立发布，应用化需落实任务能力、授权与运行维护责任。作者开放时间、资格核验细则及具体字段权限待落实；教程/资源先开放维护、应用先申请更新、后台正式发布的分工已确认，不从“后续可维护”推导可自行上架。

实际提供者与维护人的人选、第三方能力是否可在 MakeNow 承接、首发应用名单、生产定向链接及接口仍需确认。此细化不新增付费分成、交易、模型托管或任意代码执行业务。
