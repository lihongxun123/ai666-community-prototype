# 原型前需求审查记录

日期：2026-09-25。范围：全站需求集中评审稿、C 端流程、B 端内容维护、跨产品流程，以及本次同步的既有架构与内容文档。产品阅读入口为[全站需求集中评审稿](product-requirements-review.md)。

当前停在产品原型之前。分轮确认后共有 43 项有效主决定、1 项取消；第 1—5 节保留此前审查与同步记录，第 6 节为最终需求复核结果。剩余产品细节见总入口第 9 节；纸面验收不代表真实系统通过。

## 1. 初稿阶段的独立交叉审查与修正

两位参与编写不同文档的代理分别审查其未编写的文档，再针对修正结果复核。首轮发现 5 项 P1、6 项 P2，均已处理；针对性复核未发现剩余 P1，新增的两项 P2 也已修正并做局部自检。

| 问题 | 修正结果 |
| --- | --- |
| 将移动端可用与社区内运行混为一谈 | 使用设备和运行承载方分开判断，简单应用也可由 MakeNow 承载 |
| 将 MakeNow 工程权限套用所有资源 | 三层工程权限限定于 MakeNow，其他附件按自身授权判断 |
| 搜索历史存在跨身份混用风险 | 当前身份、当前会话隔离，退出或切换清理查询缓存 |
| 工程编辑入口表述不一致 | 社区承担发现与说明，实际工程操作进入 MakeNow |
| 将已确认的活动与商业规则再次列为新决策 | 待确认项仅涉及改版联动验收覆盖，不重做既定规则 |
| 作品更新缺少活动锁定分支 | 区分可修改期与截止、评审锁定期，保留投稿材料关系 |
| 应用提交超时直接重试可能重复收费 | 增加结果待确认状态，先查询或反馈，不盲目重提 |
| 内容下架与工程仍可公开时入口规则冲突 | 原内容入口遵循内容、引用关系与工程权限的共同限制，其他合法独立入口单独判断 |
| MakeNow 回流丢失活动语境 | 保留活动关系，返回时复查截止和资格；转为普通发布须本人选择 |
| 账号切换或解绑缺少私有缓存处理 | 重新核验当前身份，清理跨产品私有缓存，不迁移或删除原账号资产 |
| 草稿期限误覆盖已提交或退回材料 | 建议期限仅适用于未提交私人草稿，正式提交和退回材料保留原记录 |
| 未来作者直接编辑应用的验收早于供稿阶段 | 首阶段验收改为提交更新申请，直接编辑验收留待后续开放 |
| 评论修改沿用正文审核可能扩大审核范围 | 按实际评论治理策略处理，决策摘要补齐点赞与评论规则 |

## 6. 最终需求复核

### 结论与边界

C 端 12 项、B 端 13 项、跨产品 14 项、总体承接 4 项主决定曾逐项确认，D-B13 取消。社区默认推荐、后台编排帖子并保留最新继续适用；此前“举报结果通过我的通知找回”已被本轮取消用户举报流程的决定替代。现行需求以总入口和分项需求为准，不能把本段历史记录作为当前原型的举报依据。

本次两位独立复核者分别检查 C/B 内容与旧底稿、积分任务与跨产品权限，并直接对照文件；主任务核实后修正。已确认的方向、授权和生产边界保持不变。
