# B 端设计所需的 C 端联动清单

本表表达业务依赖，不定义数据库、接口或后台最终页面数量。当前 C 端范围以阅读台 37 个注册页面标识及本版页面需求为准；PC 与移动端分别承载，不要求两端独立页数量一致。官方应用、教程维护与资源合并应用沿用已确认决定。

| 业务对象 | B 端需维护或处理 | C 端读取与用户动作 | B 端设计必须说明的边界 |
|---|---|---|---|
| 首页、专题、推荐位 | 选择公开对象、顺序、生效范围、封面与标题 | 查看编排并进入原对象 | 未发布对象不能进入正式推荐；原内容下架后的占位/移除；同序稳定排序 |
| 作品、帖子 | 审核、发布、下架、违规原因及引用关系 | 作者管理与普通用户浏览分别展示状态 | 审核通过不等于已发布；修改版和公开版分离；下架不删除合法关联讨论 |
| 教程 | 官方维护正文、板块、媒体与关联应用 | 筛选阅读、章节定位、打开关联能力 | 无用户维护入口；关联应用不可用不等于教程整篇不可读 |
| AI 应用 | 展示内容、预览、能力形态、设备支持、有效执行入口 | 先了解能力，再到 MakeNow 使用 | Agent/Skill/工具不作为互斥媒体类型；缺失入口不可假装可执行；账号互通已完成，以同一账号继续；素材和结果等深度互通尚无方案和开发 |
| 圈子 | 基础资料、可见性、开放状态、公告/置顶、推荐 | 加入/退出、浏览、圈内发帖和评论 | 普通关闭与治理封禁不同；退出不删除历史帖；置顶不重复混入普通流 |
| 生成能力 | 模型可用性、输入约束、参数选项、报价、任务结果 | 校验输入、确认消耗、等待结果、主动发布 | 报价变化再次确认；轮询超时不等于失败；失败不等于已退款；结果不自动公开 |
| 活动 | 周期、任务条件、解锁方式、投稿类型、奖励及发放结果 | 查看说明、做任务、投稿、查看完成和到账 | 同一作品可关联多个活动；同一活动同一期去重，活动开始前已发布作品不可参加，不提供例外配置；固定七天与参与后七天不同；不从说明文字解析结构化奖励；自动奖励不生成手动领取按钮 |
| 签到 | 周一至周日基础奖励、连签规则、有效配置 | 签到弹层、连续天数及奖励结果 | 漏签与周切换、配置生效日、时区、重复签到的处理；配置金额不写死到页面 |
| 邀请 | 阶段条件、有效绑定、各维度上限、异常复核 | 邀请方式、规则、好友阶段、已到账奖励 | 完成待发与已发分开；超限与延迟不能混称；规则调整由运营人工核对影响与处理 |
| 限时积分 | 发放有效期、流水、到期、原批次返还 | 余额、到期提示、明细、交易校验 | 缺失有效期不可发放；最早到期先扣；返还不能重置有效期；未知不能按零展示 |
| 商城兑换 | 商品/站点、库存、生效范围、价格、权益交付和异常处理 | 确认兑换、结果、历史记录 | 价格变更再次确认；已扣分未交付不报成功；商品停用不删除旧记录；卡密仅对应本人兑换 |
| 账号与关系 | 身份能力、账号限制、绑定状态、治理结果 | 登录、绑定/换绑/解绑、关注/粉丝 | 不可解除唯一可用登录方式；占用账号不覆盖；公开页不暴露绑定资料 |
| 通知与反馈 | 通知类型、业务对象、可读原因与操作结果 | 进入具体对象或获知失效原因 | 失效不跳无关对象；内部审核/风控信息不原样下发为文案 |

## 状态设计的共同要求

每个可处理对象至少在设计说明中回答：谁触发、前置条件、成功后是什么、失败后保留什么、结果未知如何恢复、能否撤销/重试、是否影响已存在记录。无需为每一种情况增加页面；字段提示、按钮状态、同一弹层结果可以承载。

状态图不得只写“待审核→通过→成功”。例如投稿要区分内容审核、是否公开、投稿资格和奖励到账；兑换要区分请求受理、积分结算和权益交付。用户可见文案使用业务语言，后台保留可追溯处理结果。

### 投稿内容下架与奖励

下架保留投稿记录；公开型任务发奖前重校验，无关任务不受影响。恢复沿用原记录重校验，不重复奖励，已结束活动不自动补发。普通下架不自动追扣；违规作弊由后台按规则处理并记录原因、积分流水。


### 列表排序配置

首页爆款作品由后台选择并控制展示顺序，C 端按返回顺序展示，不按点赞、收藏或发布时间自行重排；分类筛选保留相对顺序。现有管理端代码已确认爆款标记维护，尚未找到普通作品独立排序入口，排序配置与返回顺序的映射在 B 端设计时补齐，不能复用模板或广告位排序充当作品排序。

PC 全部应用先展示已配置运营顺序的应用，按配置顺序排列；未配置项排在其后，按首次公开时间倒序。同序或同时间按稳定标识排序，重新上架不重置首次公开时间。精选应用 Banner 使用独立运营选品与顺序，只推荐公开且可用应用，空配置隐藏；手机最新上线继续按首次公开时间倒序，两者不混用。

圈内多条置顶按管理员配置的置顶顺序展示，同序按稳定标识排序；普通帖按首次公开时间倒序，同时间按稳定标识排序。置顶帖不在普通流重复出现，取消置顶回到原首次公开时间对应位置，编辑不刷新位置。


### 搜索推荐与检索联动

热门词、精选专题及精选应用分别维护对象／词条、顺序和启停；无配置隐藏，活动不进入默认推荐。七类结果读取各自有效公开字段，原内容改名、发布、下架或权限变化同步检索有效性，不能另建失去同步的正文副本。检索按search页面的字段与相关性规则执行，逐项核对全文字段、索引延迟及权限过滤；不要求原型实现检索服务。


### 草稿保存与引用保护

同账号跨端恢复已成功保存的字段及上传成功并保存关联的素材；手动草稿最近成功保存起30天，打开不续期。失效素材标记并允许替换，保留其余内容。草稿删除二次确认且无回收站，不连带删除来源作品、生成记录或其他内容使用中的素材。待审、退回稿及生成记录不适用草稿期限；草稿存储与物理素材清理由研发核对实现，不新增运营代编辑用户草稿的权限。


### AIGC生成资产

AIGC生成结果属于用户资产。本期不设置保存到期时间，不增加到期提醒、到期失效或按期限自动清理；手动草稿30天规则不适用于生成结果与生成记录。生成记录本期不支持用户删除，进行中与已结束任务均不提供删除或批量删除入口，不设置删除确认及回收站。保存到草稿、发布作品与生成来源保留关联，草稿到期或删除不连带删除生成资产；既有内容权限和违规治理规则仍分别执行。本期不处理保存期限，不将其宣传为永久存储服务承诺。后台治理不据此获得任意删除资产权限；本轮不新增清理配置。


### 已发布内容删除与引用

本人删除作品／帖子需确认且无回收站；删除后引用方隐藏引用区，不显示失效占位，保留自身正文与讨论。原详情及所属评论不再公开展示，必要参与和奖励记录保留并注明原内容已删除。发奖前校验公开条件，普通删除不自动追回已到账奖励，不删除生成资产。此规则与父评论删除保留回复占位分别处理。


### 个人资料审核沿用现状

不新增个人资料人工审核工作台或逐字段待审版本。昵称／头像变更在整组资料保存时同步机审；当前简介、性别未见机审调用。保存结果与数据库写入一致性另列研发修复项：现有后端先写入后检查，失败未见回滚，不能将页面失败当作资料未变更的证据。


### 邀请码补绑资格

新旧账号未绑定时均可绑定，本期无注册后补绑期限。以首次成功绑定为准，拒绝自邀、无效码和重复绑定，不提供换绑／解绑入口。登录绑定失败不影响登录，既有关系不能被新链接覆盖；关系、阶段资格与奖励到账独立，旧账号补绑不承诺历史行为自动补算或补发。


### 活动与邀请规则调整

活动与邀请规则调整由运营人工控制，沿用现有后台编辑能力，不新增规则版本管理、按用户分组或自动兼容旧规则能力。活动开始后尽量不改奖励、门槛和期限；确需调整，由运营先核对受影响用户并说明变更，已完成任务与待发奖励等特殊情况人工核对处理。保留现有参与记录与积分流水便于核查；不据此新增任意发分、改账权限。此项属于运营操作约束，不增加C端版本选择、自动补算或新弹层。


### 兑换异常处理

已扣未交付且无终局结果显示兑换结果确认中，仅查询原记录；明确失败区分未扣分、积分返还处理中、已返还。长时间无结果通过现有客服入口人工核对，不自动重建订单。商品下架保留成功记录及卡密查看复制；原卡密自身有效期不变。实际履约与账务结果映射交研发，不增加独立工单系统或新改账权限。


### 统一业务时间与字数

业务时间采用北京时间，开始包含、结束不包含，日／月限额按北京时间切换；C端展示与B端配置使用相同口径。文本按用户可感知字符计数，组合表情算1个，内部空格和换行计入，各字段限额不变。前后台与服务端校验需一致，不由浏览器时区或UTF-16长度代替已定规则。


### 原积分过期后的返还

返还沿用原批次到期时间，未过期部分恢复可用，已过期部分不恢复并说明原积分已过期；混合批次分别判断。用户侧区分返还处理中、已返还及恢复可用金额；特殊补偿由运营人工核对，使用既有授权并单独留痕，不新增自动补偿或通过返还续期。具体账务字段、枚举及混合批次数据由研发交接核对。
