## 原型台如何罗列

### 1. 页面内增加查看方式，不扩充左侧一级导航

在现有“页面原型”工具区提供：

```text
移动端 / PC端    产品方案 / 页面原型
页面    弹层与提示（按业务用途计数）

弹层与提示选中后：
小图 + 名称快速选择  →  带原页面背景的展开效果  →  页面需求 / 交互规则
```

左侧仍是首页、社区、创作与发布、活动、商城、我的等业务页面；“弹层与提示”是所选页面的查看方式。数量按当前设备可用的业务场景去重，不累计提示文案、不重复计算成功/失败变体。移动端没有该浮层而是页面时，提供对应页面链接，不虚构移动端弹窗。

已有单独展示的登录、每日签到、兑换弹层保留当前审阅入口，登记为唯一展示对象；其他页面只引用它们。此次不以整理弹层为由再改一轮已确认导航。

### 2. 四类对象采用不同表达方式

| 对象 | 展示方式 | 示例与必要规则 |
|---|---|---|
| 业务弹层 / 底部层 / 全屏覆盖层 | 默认展开，保留宿主背景；小图快速切换 | 登录、兑换、绑定、签到、生成记录、邀请规则。注明打开入口、关闭方式、返回目标与输入保留 |
| 下拉菜单 / 锚定气泡 | 在真实控件位置展开，点外部收起 | 模型、比例、投稿活动、话题多选、头像菜单。保留已选值、边界翻转和遮挡关系 |
| 业务专用提醒 | 在业务宿主显示，并提供“重播” | 积分到账/退回、签到奖励数字、临期积分、任务引导、精选奖励、运营推广。说明触发来源、频控、优先级与确认语义 |
| 通用轻反馈 / 字段校验 / 媒体控制提示 | 通用反馈页放代表组件，各业务页说明具体规则并能交互触发 | 复制成功、上传失败、必填校验、请求超时、播放器进度气泡；不新增逐条状态卡 |

保留已确认“通用反馈”三个分区、七个样例。可在“局部反馈”内补一个轻提示可交互示意，切成功/提醒/失败文案，不增加左侧页面或恢复旧 53 项状态目录。媒体播放控件放到媒体详情演示，不塞入通用异常页面。

### 3. 同一业务只保留必要变体

例如兑换沿用已确认的“确认兑换 / 兑换成功 / 积分不足 / 兑换失败”。库存、停售、价格变化等在失败规则和示例文案中表达；结果未知复用“查询原请求、不重复提交”的通用规则，不新增一整页。

绑定手机号的输入、验证码已发送、发送失败是同一个表单的交互过程；不为每步再生成一张状态页面。微信码加载失败、失效和刷新在二维码区域切换。删除确认复用一个确认模板，作品、帖子、草稿等使用各自对象名称与影响说明。

图片、视频、文本属于内容差异，不能为了减少状态把不同媒体功能合并掉。PC 图片/视频生成预览与 H5 含文本的全屏结果查看应分别按实际能力表达。

## 统一交互规则需要补什么

每项展示对象登记：唯一编号、所属页面、触发控件、适用设备、形态、正常样本、必要变体、确认动作、关闭/返回、输入保留、数据来源、线上核查状态。共享对象引用唯一编号，避免同一登录弹窗出现多套稿。

1. **遮挡和返回**：PC 居中层、H5 底部层、全屏层分别规定滚动容器；关闭后回到原页面、原列表位置，菜单收起不清空已选内容；浏览器返回优先关闭可返回的覆盖层。键盘焦点进入弹层并在关闭后归还入口。
2. **嵌套**：业务操作优先当前层内切换；媒体全屏预览或安全验证确需二层时，返回恢复上一层。禁止多个运营弹层同时遮挡，具体优先级和频控应按业务确认后写需求。
3. **提示**：不遮挡顶栏、底部主按钮和手机安全区；字段错误靠近字段，按钮处理中防重复；重复网络错误合并，短时间消息按队列展示。持续结果保留在业务区域，不能只闪一下就消失。
4. **触屏**：PC hover 说明不能作为 H5 唯一说明入口；重要规则采用可点击说明或常驻短文。原生 title/无障碍名称不计独立弹层。
5. **模拟与复现**：原型提供固定样本与重置/重播，不连接真实奖励、扣费、绑定、删除、通知确认。自动提示要有手动入口，避免刷新后受频控影响再也看不到。
6. **非模态奖励反馈**：积分数字、到账/退回气泡及普通轻提示不加遮罩、不夺焦点、不要求业务确认。同笔积分事件按登记落点选择数字浮层或顶部气泡，不能同时重复播放；原型可分别重播样本。可视文字与无障碍播报一致，并适配减少动态效果设置。当前源码退回可视文字与到账播报存在不一致风险，运行行为仍待专项核验。

## 执行顺序与验收

第一步：只实现原型台的“弹层与提示”查看方式、唯一对象引用、小图切换和定位链接。以已有兑换层、编辑资料绑定层、AIGC 选择气泡、积分到账提示覆盖四类承载，自检两端尺寸与关闭返回。

第二步：按上表补齐业务对象；每完成一个模块同步该页需求。保持已确认正常页优先，不重复制作异常整页。由实际差异决定样例数量，不预先规定每个页面必须有几种状态。

第三步：补全全局运营/事件提示的手动样本和轻反馈交互，做一次入口覆盖检查。源码疑似闲置组件、第三方 Markdown 内部预览、iOS 原生全屏独立列待验证，不当作已完成页面。

验收：每个在范围内的浮层都有宿主与入口；两端差异可定位；同对象无重复稿；默认展开可直接审阅，关闭可回到正确背景；必要变体可切换；菜单不越界，弹层不被裁切，滚动不穿透；输入与列表位置按规则保留；全程仅本地模拟。提交成功、发奖、到账等静态演示不作为线上验收。

初次盘点仅形成方案。后续执行进度（2026-10-02）：已实现第一步的原型台入口、场景定位与四类样本：兑换、账号绑定、创作参数菜单、积分到账/退回。各样本复用已有业务页，补充独立本地演示入口。其余清单仍待逐模块接入，未修改线上配置或真实 C端代码。
